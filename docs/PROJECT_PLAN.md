# 项目执行计划与分工

> 项目：智能机械臂垃圾分类与管理系统  
> 计划周期：约 6 周；目标完成时间：2026 年 12 月初  
> 适用对象：A、B、C、D，以及后续参与项目的 Agent。

## 1. 目标与分工原则

本项目需要完成从视觉识别到机械臂抓取、事件记录和 Web 展示的完整闭环：

```text
USB 摄像头 → YOLOv8 识别 → 坐标转换/任务编排 → ROS2/Arm_Lib 控制
    → 抓取复检 → 事件入库 → Web 管理界面
```

扩展功能包括手势控制（E1）与语音控制（E2）。

分工遵循以下原则：

- 每位成员拥有可独立验收的主模块，不以“协助”作为主要贡献。
- B 承担视觉识别、跨模块集成、版本发布和进度协调；原先由 A 承担的集成职责转交给 B。
- F3 采用全栈交付：D 同时维护 Web 前端、Java 后端与数据库，降低管理平台的前后端联调成本。
- 真实机械臂动作只能经过 C 维护的安全控制边界；手势和语音不得绕过该边界直接控制舵机。
- 所有跨模块事件使用统一的 `taskId` 追踪；接口优先于联调实现。

## 2. 成员职责总览

| 成员 | 主责模块 | 次要职责 | 最终可展示成果 |
| --- | --- | --- | --- |
| A | 手势控制（E1）、语音控制（E2） | 数据集标注规范/抽检、系统测试、验收材料 | 双模态控制演示、数据质量记录、验收报告 |
| B | 视觉识别（F1）、总体集成 | 任务管理、接口冻结、发布 | 模型指标、端到端系统、最终发布版本 |
| C | 机械臂控制（F2）、标定、ROS2、安全 | 硬件测试、抓取复检 | 任意位置抓取、安全降级、急停演示 |
| D | F3 全栈管理平台、数据库、异常事件（F4） | JUnit 测试、接口文档 | API、Web 管理页面、异常日志、后端测试报告 |

## 3. A：手势、语音、数据质量与验收

### 3.1 手势控制（E1）

使用 OpenCV/MediaPipe 或同等方案实现启动、暂停、复位、取消、急停等有限命令。手势模块只输出统一命令，不能直接调用 `Arm_Lib`。

```text
摄像头 → 手势识别 → 连续帧确认 → GestureCommand
       → B 的统一编排 → C 的安全校验 → 机械臂执行
```

要求：连续约 5 帧结果一致才触发；同一命令触发后冷却 10 秒；记录识别结果、置信度、时间和是否执行。目标指标：准确率不低于 90%，响应 P95 不高于 1 秒，不产生越界动作。

### 3.2 语音控制（E2）

支持开始分类、暂停任务、复位、取消和急停等有限命令。语音模块只输出 `VoiceCommand`，经 B 的统一编排与 C 的安全校验后才可执行：

```text
语音输入 → 唤醒/命令识别 → VoiceCommand
         → B 的统一编排 → C 的安全校验 → 执行
```

目标指标：4 人、2 种环境、每人 5 条命令，共 40 次测试，激活率不低于 90%，响应 P95 不高于 2 秒；20 条无关语音中误触发率不高于 5%。语音与手势的急停命令必须遵守 C 定义的最高安全优先级。

### 3.3 数据质量、测试与验收

- 与 B 制定数据集标注规范，抽检不少于 20% 的标注；若差异超过 5%，协助完成全量复核。
- 编写端到端验收检查表，整理演示流程、截图、录像和测试原始记录。
- 对 Python 扩展控制代码使用 `unittest` 或 `pytest`；参与 B 的视觉模块与 D 的全栈接口复核。

## 4. B：视觉识别、总体集成与发布

### 4.1 职责

- 建立并维护任务看板、Issue、里程碑和风险清单。
- 冻结跨模块字段与接口；接口有破坏性变更时组织评审。
- 负责主分支合并、发布版本、配置归档和最终演示流程。
- 组织至少两轮完整的端到端联调与一次验收演练。
- 自己提交的核心代码必须由 A、C 或 D 审核后合并。

建议 Issue 范围：`F1-dataset`、`F1-yolo-training`、`F1-edge-inference`、`F2-calibration`、`F2-arm-control`、`F2-safety`、`F3-backend-events`、`F3-dashboard`、`F4-fallback`、`E1-gesture`、`E2-voice`、`integration-release`。

### 4.2 视觉识别（F1）

- 建立四类垃圾数据集；每类不少于 300 张，总量不少于 1200 张。
- 按训练/验证/测试 = 7:2:1 划分数据；保留数据版本、标注规范和训练配置。
- 训练 YOLOv8 基线模型，输出 mAP、各类 Recall、混淆情况和典型误检/漏检样例。
- 实现摄像头读取、图像预处理、推理、目标选择与低置信度拒绝。
- 部署到最终设备或等效运行环境，测量真实推理延迟。

目标指标：mAP@0.5 不低于 0.80；每类 Recall 不低于 0.75；推理延迟 P95 不高于 150 ms；置信度低于 0.5 时不得下发抓取动作。

### 4.3 统一编排与端到端集成

B 维护任务流和跨模块错误传播，核心状态固定为：

```text
RECEIVED → VALIDATING → EXECUTING → VERIFYING → SUCCEEDED
                  └→ REJECTED
VERIFYING → RETRYING（最多一次）→ SUCCEEDED / FAILED / SAFE_MODE
```

负责把 A 的手势/语音命令、B 的视觉结果、C 的执行状态与 D 的全栈管理平台串联起来；提供启动顺序、一键或分模块启动脚本、环境变量示例和演示用配置。

## 5. C：机械臂控制、标定、ROS2 与安全

### 5.1 控制适配层

把课程示例中的 `Arm_Lib` 调用整理为稳定接口，例如：

```python
move_joint(servo_id, angle, duration_ms)
move_pose(joints, duration_ms)
open_gripper()
close_gripper()
move_home()
emergency_stop()
read_servo_state()
```

所有动作必须进行角度、时长、通信状态检查。业务模块不可直接散落调用 `Arm_Device`；应提供 Mock 控制器，以便没有硬件时联调。

### 5.2 标定、抓取与复检（F2）

- 建立 3×3 标定网格，完成像素坐标到工作台坐标的映射。
- 实现 `pixel_to_world(x, y)`，保存标定文件、误差数据和重新标定流程。
- 实现待机、抓取、抬升、移动、投放、复位等动作序列。
- 接收 B 下发的目标类别和坐标，执行抓取并上报状态。
- 抓取后进行视觉复检；首次失败最多重试一次，之后进入失败或安全模式。

验收目标：10 个未参与标定的位置中，首次成功率不低于 85%，允许一次重试后不低于 95%，完整周期 P95 不高于 15 秒；工作区外坐标必须 100% 拒绝。

### 5.3 ROS2 与安全控制

- 实现机械臂控制节点、状态发布、取消/暂停/急停接口。
- 堵转约 3 秒、通信超时约 2 秒或连续丢失 3 个心跳时停止动作。
- 支持 K2 急停和安全姿态恢复。
- 与 D 共同覆盖异常场景：C 负责硬件停止和保护，D 负责事件持久化和页面可观测性。

真实硬件测试必须有人在旁值守并可立即按下急停；未知状态默认停止，不继续执行动作。

## 6. D：F3 全栈管理平台、数据库与异常事件

### 6.1 Java 后端和数据库

建议采用 Java 17、Spring Boot、Spring Web、Spring Data JPA/MyBatis 与 MySQL（开发阶段可用 H2）。使用数据库迁移工具管理表结构。

主要数据：任务记录、识别事件、机械臂执行记录、异常事件、系统状态。

最小 API：

```text
POST /api/tasks
GET  /api/tasks/{taskId}
GET  /api/events
GET  /api/statistics
GET  /api/exceptions
GET  /api/system/status
POST /api/tasks/{taskId}/cancel
```

提供 OpenAPI/Swagger 文档、统一错误响应和 Mock 数据。重复上报同一事件时必须幂等。

### 6.2 Web 管理前端（F3）

D 对 F3 采用全栈交付：建议使用 Vue 3 + TypeScript + Vite；若工程最终选择 React，则保持同等功能和接口约定。至少实现以下页面：

1. **系统概览**：摄像头、识别服务、机械臂、后端连接状态；任务总数、成功数、失败数、成功率和类别统计。
2. **实时事件**：显示最新识别类别、置信度、目标坐标、任务状态、动作结果和时间；支持轮询或 SSE/WebSocket 更新。
3. **分类统计**：按类别、日期统计数量、成功率、失败率和任务耗时。
4. **异常日志**：展示低置信度、坐标越界、动作超时、抓取失败、服务不可用等异常，并可按时间、类型和任务编号筛选。

完成要求：事件在后端产生后 P95 于 1 秒内在页面展示；字段完整；网络或服务异常时有明确提示而非白屏。D 应同时维护前端调用的 API 类型定义或接口说明，确保前后端字段同步。

### 6.3 异常记录与降级（F4）

至少支持并持久化以下异常：

- `LOW_CONFIDENCE`
- `OUT_OF_BOUNDS`
- `ARM_TIMEOUT`
- `GRAB_FAILED`
- `SERVICE_UNAVAILABLE`

每条记录至少包含 `taskId`、异常类型、发生时间、所属模块、错误说明、是否重试与最终处理结果。D 负责让异常可查询、可统计、可在管理页面显示；C 负责机械臂安全停机动作。

### 6.4 JUnit 测试

使用 JUnit 5 和 Mockito 覆盖 Controller 参数校验、Service 状态转换、幂等、异常持久化、统计计算、数据库读写、下游超时和错误响应。JUnit 仅用于 Java 后端；Python 的视觉与控制代码使用 `unittest` 或 `pytest`。

## 7. 跨模块接口与交付边界

| 提供方 | 使用方 | 必须交付的内容 |
| --- | --- | --- |
| B（视觉） | C、D | `taskId`、类别、置信度、像素坐标、检测框、时间、图像引用 |
| C（控制） | B、D | 执行状态、舵机状态、抓取结果、错误码、耗时 |
| B/C | D | 识别、控制、复检与异常事件 |
| D（F3 全栈） | 全员 | API、统计数据、实时事件、系统状态和 Web 管理页面 |
| A（扩展控制） | B/C | `GestureCommand`、`VoiceCommand`，含来源、时间和命令类型 |
| B（集成） | 全员 | 版本清单、启动顺序、环境配置、发布说明 |

视觉模块建议输出如下结构；具体字段可在 OpenAPI 冻结后扩展，但不得随意改名：

```json
  "category": "plastic",
  "confidence": 0.91,
  "pixelX": 426,
  "pixelY": 237,
  "box": [380, 190, 472, 284],
  "imagePath": "...",
  "timestamp": "..."
}
```

## 10. Agent 执行约定

后续 Agent 接任务时应以本文件为边界：先确认所属模块、输入输出接口和验收条件，再修改代码。任何跨模块字段变更必须同时更新接口文档、调用方和测试；无法兼容时由 B 决定版本迁移方案。Agent 不应绕过 C 的安全控制直接连接真实机械臂，也不应绕过 D 的后端接口直接伪造正式统计数据。
